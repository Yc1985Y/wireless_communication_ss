# 03I BICM-LDPC 编码链路：5G NR LDPC 与比特交织编码调制

## 实验目的

1. 搭建 5G NR LDPC（3GPP TS 38.212）编码 + QPSK/16-QAM 映射 + AWGN + 软解调 + 迭代置信传播译码的完整 BICM 链路。
2. 在同一 $E_b/N_0$ 口径下比较编码与未编码的 BER，定量给出编码增益及其出现的信噪比区间；验证"编码只在瀑布区之后才带来增益"这一 BICM 常识。
3. 考察译码迭代次数、码率、调制阶数对性能的影响，并从解调器输出 LLR 的分布解释软信息的作用，说明 $E_s/N_0$ 与 $E_b/N_0$ 的换算关系（含码率 $R=k/n$）。

## 方法与参数

**BICM 链路。** 信息比特 $\mathbf b\in\{0,1\}^{K}$ 经 5G LDPC 编码（含 3GPP 速率匹配与面向调制阶数的输出交织）得到码字 $\mathbf c\in\{0,1\}^{N}$，按 $q=\log_2 M$ 比特一组映射为星座符号 $\mathbf x\in\mathcal X^{N/q}$：

$$
\mathbf y=\mathbf x+\mathbf n,\qquad \mathbf n\sim\mathcal{CN}(0,N_0),
$$

解调器按 APP 准则输出逐比特对数似然比

$$
L(b_i)=\ln\frac{P(b_i=1\mid y)}{P(b_i=0\mid y)}=\ln\frac{\sum_{x\in\mathcal X_i^1}\exp(-|y-x|^2/N_0)}{\sum_{x\in\mathcal X_i^0}\exp(-|y-x|^2/N_0)},
$$

（Sionna 的 `Demapper` 采用 $\ln\frac{P(1)}{P(0)}$ 约定，与上式同号：$b=1$ 时 LLR 为正；其 `no` 参数即复噪声总方差 $N_0=2\sigma^2$，故 LLR 中不再出现独立的 $2/\sigma^2$ 因子。）LLR 送入 `LDPC5GDecoder` 做置信传播：默认校验节点更新为精确和积（`cn_update='boxplus-phi'`），`num_iter` 为泛洪调度的完整轮数（无早停），最多迭代 `num_iter` 次，硬判决输出 $\hat{\mathbf b}$，与 $\mathbf b$ 逐比特比较得 BER。`LDPC5GEncoder(k, n, num_bits_per_symbol=q)` 的参数顺序是 (k, n)，内部按 3GPP 规则选 BG1/BG2、完成前 2Z 打孔与截尾，并把码字按调制阶数做输出交织；`mapper(cw)` 直接使用该编码器输出，解码器会自动反交织（若再人为交织一次，BER 会退化为 0.50）。

**$E_b/N_0$ 与 $E_s/N_0$ 的换算。** AWGN 信道的噪声方差按 $E_s/N_0$ 设定，仿真中以其倒数 $N_0=1/(E_b/N_0\cdot q\cdot R)$ 给出（信号功率归一化为 1），即

$$
\frac{E_s}{N_0}=\frac{E_b}{N_0}\cdot q\cdot R,\qquad q=\log_2 M,\ R=\frac{k}{n}.
$$

因此同一 $E_b/N_0$ 下，编码链路（$R<1$）的符号信噪比更低，这是低信噪比处"编码反而更差"的直接原因；只有译码增益超过 $10\log_{10}(1/R)$ 的速率损失，编码才划算。全部曲线横轴统一为 $E_b/N_0$，未编码曲线的 $R=1$。

**参数表**

| 参数 | 模板演示链路 | 扩展实验链路 |
| --- | --- | --- |
| 信息比特 $K$ / 码字比特 $N$ | 600 / 1200 | 1200 / 2400 |
| 码率 $R=k/n$ | 1/2 | 1/2 |
| 调制方式 | QPSK（$q=2$） | QPSK 与 16-QAM（$q=4$） |
| 批大小 | 16 码字（每点 9600 bit） | 256 码字（每点 307200 bit） |
| 译码迭代次数 | 8 | 20（迭代对比另取 2/5/8/20） |
| $E_b/N_0$ 范围 | 0 / 2 / 4 / 6 dB | 0~4 dB，步长 0.5 dB |
| 码率对比 | — | $R=1/3$ (600,1800)、$1/2$ (600,1200)、$3/4$ (900,1200) |
| 编码器 | `LDPC5GEncoder(k, n, num_bits_per_symbol=q)` | 同左（自动选 BG1/BG2 并做速率匹配 + 输出交织） |
| 译码器 | `LDPC5GDecoder(enc, hard_out=True, num_iter=...)` | 同左（精确和积、泛洪 BP） |
| 随机种子 | `torch.manual_seed(42)`、`np.random.seed(42)`、`sionna.phy.config.seed=42` | 同左 |

## 分析

编码增益与速率损失的分界在 $E_b/N_0\approx1$ dB 处清晰可见。0 dB 时编码链路 BER 0.161589 反而是未编码 0.078954 的 2.05 倍：R=1/2 使符号信噪比降低 3 dB（$E_s/N_0=E_b/N_0\cdot qR$），短码在瀑布区之前无法用冗余抵消这一损失；16-QAM 更明显，0 dB 时编码（0.190951）是未编码（0.141104）的 1.35 倍。进入瀑布区后曲线断崖下降：QPSK 编码从 0.5 dB 的 0.103271 跌到 1.5 dB 的 $2.51\times10^{-4}$，1 dB 内下降 412 倍（2.61 个数量级）；以 1.5 dB 处编码相对未编码的倍数计，编码增益为 186 倍（2.27 个数量级）。4 dB 处 QPSK 与 16-QAM 编码误码均为 0，而未编码仍有 $1.25\times10^{-2}$ 与 $5.88\times10^{-2}$。迭代次数是最直接的可调旋钮：2 dB 处 2 次迭代 0.099935、20 次为 0；1.5 dB 处 8 次迭代 $2.76\times10^{-2}$、20 次 $3.16\times10^{-4}$（改善 87.5 倍），说明置信传播需足够多轮才能把软信息可靠性传遍 Tanner 图；在 0 dB 这类远低于门限的信噪比，加迭代几乎无效（0.185293→0.163988，仅 13%），因为此时 LLR 大量处于错误一侧，迭代只是在错误信念上反复加固。码率体现编码增益与频谱效率的折中：1 dB 处 BER 随码率由 $1.99\times10^{-3}$（R=1/3）升到 0.031348（1/2）、0.100447（3/4）；0 dB 时 R=1/3（0.113151）反而优于 R=1/2（0.165918），因低信噪比下冗余收益超过 1.76 dB 速率损失；R=3/4 在 0 dB 又降到 0.137951，说明低信噪比时"码率—增益"不是单调关系，而由瀑布区位置与速率损失的相对大小决定。LLR 分布给出机制：16-QAM 平均 $\lvert L\rvert$ 从 0 dB 的 1.90 升到 3 dB 的 3.22，软信息可靠性直接决定收敛轮数。

## 结论

1. 5G NR LDPC + QPSK/16-QAM 的 BICM 链路在 $E_b/N_0$ 统一口径下正确实现：未编码曲线与理论值最大绝对偏差 $1.94\times10^{-3}$（相对 1.4%），编码后在 4 dB 处 QPSK/16-QAM 均达到 0 误码（95% 上界 $9.8\times10^{-6}$），而未编码分别为 $1.25\times10^{-2}$ 与 $5.88\times10^{-2}$；22 项接口检查（编码器参数顺序、2Z 打孔与截尾、输出交织、LLR 符号与幅度、Eb/N0 含码率、16-QAM b0 为 I 路符号位、未编码同能量口径）全部通过。
2. 编码并非在所有信噪比都有效：R=1/2 的速率损失使 $E_b/N_0\le1$ dB 时编码 BER 高于未编码（0 dB 处 0.161589 对 0.078954，2.05 倍），编码增益只在瀑布区之后出现，且瀑布过渡极陡（1 dB 内下降 2.61 个数量级）。
3. 迭代次数与码率是两个互补的调节手段：20 次迭代相对 2 次在 2 dB 处把 BER 从 0.099935 降到 0，1.5 dB 处改善 87.5 倍；1 dB 处 BER 随码率 1/3→3/4 从 $1.99\times10^{-3}$ 升到 0.100447，而 0 dB 处"低码率反而更好"说明低信噪比下多冗余比高频谱效率更重要。
